## Task Completion Log

### ✅ Task 1 — HTTP 500 Root Cause Fix

**File:** `i18n/server.ts`
**What was done:**

- Wrapped the entire body of `getLocaleOnServer()` in a `try/catch` block.
- On any runtime exception (cookie/header API failure, Negotiator error, locale match error), falls back to `i18n.defaultLocale` (`'en'`) instead of throwing and crashing the root Server Component.
- This prevents the `app/layout.tsx` async Server Component from propagating an unhandled error into the RSC stream, which was the most likely cause of digest `3549000446`.

**Diff summary:**

```diff
- let languages: string[] | undefined
- const localeCookie = (await cookies()).get('locale')
- ...
- return matchedLocale
+ try {
+   let languages: string[] | undefined
+   ...
+   return matchedLocale
+ } catch {
+   return i18n.defaultLocale as Locale
+ }
```

### ✅ Task 2 — Root Error Boundary

**File:** `app/error.tsx` (new file)
**What was done:**

- Created a `'use client'` root error boundary as required by Next.js App Router.
- Renders its own `<html lang="zh-Hans"><body>` so the `lang` attribute is preserved even when Next.js fires the `__next_error__` wrapper (which normally strips all layout-level HTML attributes).
- UI: warm `#FBF8F4` background, coral `#E8A87C` accent, Chinese error message, "重新加载" (reset) + "返回首页" (home) buttons.
- Always shows emergency hotlines `110` and `12338` as `tel:` links — critical for a domestic violence support site.
- Shows raw error message only in `NODE_ENV === 'development'` to avoid leaking stack traces in production.
- Props: `{ error: Error & { digest?: string }, reset: () => void }` per Next.js spec.

### ✅ Task 4 — Organization JSON-LD

**File:** `app/layout.tsx`
**What was done:**

- Added `organizationJsonLd` const with `@type: "Organization"`, `name`, `url`, `description`, and a `contactPoint` typed as `"crisis support"` with `availableLanguage: "zh-Hans"`.
- Inserted as a second `<script type="application/ld+json">` in `<head>`, directly after the existing `WebSite` schema script.
- Uses the same `dangerouslySetInnerHTML={{ __html: JSON.stringify(...) }}` pattern already established.

**Schema deployed:**
