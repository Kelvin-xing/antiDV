## Summary

The product already has a coherent emotional visual direction. The warm palette, serif-sans pairing, and low-pressure tone fit the domestic-violence support use case well. The main weaknesses are not visual taste but interaction semantics, keyboard accessibility, missing focus states, and the lack of a true shared design system across pages.

The homepage is the strongest page because it includes local focus and reduced-motion handling. The chat, sidebar, header, and form layers do not consistently inherit the same rules, so the experience feels fragmented at the system level.

### Critical Findings (P0)

**SEC-0 — `/feedback` page is a public, unauthenticated admin panel**

- URL: <https://anti-dv.vercel.app/feedback>
- [app/feedback/page.tsx](app/feedback/page.tsx) fetches and renders real user conversation logs, chat transcripts, conversation IDs, and user hashes — all without any authentication gate.
- Any visitor, search engine crawler, or automated scraper can read sensitive survivor conversations.
- This is a critical privacy/security breach and also means Googlebot can (and likely will) index user data.
- **Fix**: Add route-level authentication (e.g., password-based middleware in `middleware.ts`, or remove the page from production). Add `X-Robots-Tag: noindex, nofollow` as a stopgap via `next.config.js` response headers for this route immediately.

**CR-1 — No `robots.txt` (HTTP 404)**

- `/robots.txt` returns a 404. Crawlers fall back to indexing everything, including the admin `/feedback` page and the dynamic `/chat` session.
- Without explicit `Disallow` rules, GPTBot, ClaudeBot, Googlebot, PerplexityBot, and other crawlers have no guidance.
- **Fix**: Create `app/robots.txt` (or a `robots.ts` route handler) with at minimum:

```txt
User-agent: *
Disallow: /feedback
Disallow: /chat
Disallow: /api/

User-agent: GPTBot
Disallow: /

User-agent: ClaudeBot
Disallow: /

User-agent: PerplexityBot
Disallow: /

Sitemap: https://anti-dv.vercel.app/sitemap.xml
```

**CR-2 — No `sitemap.xml`**

- `/sitemap.xml` returns no content. Google cannot discover all pages without crawling.
- The site has at least 8 distinct URL paths worth indexing: /, /resources, /stories, /stories/[id], /psych-resources, /docs-toolkit, /docs-toolkit/[templateId].
- **Fix**: Create `app/sitemap.ts` using the Next.js App Router `MetadataRoute.Sitemap` export:

```ts
// app/sitemap.ts
import { MetadataRoute } from 'next'

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    { url: 'https://anti-dv.vercel.app/', changeFrequency: 'monthly', priority: 1.0 },
    { url: 'https://anti-dv.vercel.app/resources', changeFrequency: 'monthly', priority: 0.8 },
    { url: 'https://anti-dv.vercel.app/psych-resources', changeFrequency: 'monthly', priority: 0.8 },
    { url: 'https://anti-dv.vercel.app/stories', changeFrequency: 'monthly', priority: 0.7 },
    { url: 'https://anti-dv.vercel.app/docs-toolkit', changeFrequency: 'monthly', priority: 0.7 },
  ]
}
```

### High-Priority Findings (P1)

**META-1 — No `<title>` or `<meta description>` on any page**

- [app/layout.tsx](app/layout.tsx) has no `metadata` export. All page files (`/resources/page.tsx`, `/stories/page.tsx`, `/psych-resources/page.tsx`, etc.) are `'use client'` components and **cannot export Next.js server-side metadata**.
- All pages render with no `<title>` tag in the HTML head (the browser may show an empty or fallback "小安" tab). No meta descriptions exist on any page. No Open Graph tags. No Twitter Card tags.
- This means every page shows as a blank or anonymous result in Google SERPs.
- **Fix**: Add a server-side layout wrapper per route segment that exports `metadata`, OR move the metadata into the root layout via the Next.js `Metadata` API. Because all pages are `'use client'`, the cleanest fix is to add a `layout.tsx` per route that is a Server Component:

```ts
// app/resources/layout.tsx  (Server Component — no 'use client')
import { Metadata } from 'next'
export const metadata: Metadata = {
  title: '资源导航 — 小安反家暴助手',
  description: '热线、法律援助、庇护所等反家暴资源汇总，助你在最需要的时候找到帮助。',
  openGraph: { title: '资源导航 — 小安', url: 'https://anti-dv.vercel.app/resources' },
}
export default function Layout({ children }: { children: React.ReactNode }) {
  return children
}
```

  Do the same for: /, /stories, /psych-resources, /docs-toolkit, /chat (with `noindex`).

**META-2 — No global site metadata in root layout**

- [app/layout.tsx](app/layout.tsx) does not export a `metadata` object, so there is no global site name, default OG image, or base URL configuration.
- **Fix**: Add to `app/layout.tsx`:

```ts
import { Metadata } from 'next'
export const metadata: Metadata = {
  metadataBase: new URL('https://anti-dv.vercel.app'),
  title: { default: '小安 — 反家暴AI支持助手', template: '%s — 小安' },
  description: '小安是一位专注于反家庭暴力的AI支持助手，提供情感支持、法律知识和紧急资源。',
  openGraph: {
    siteName: '小安反家暴助手',
    locale: 'zh_CN',
    type: 'website',
  },
}
```

**IDX-1 — `/chat` and `/feedback` should be `noindex`**

- The `/chat` page contains a live, ephemeral user session and is not useful as a crawled page.
- The `/feedback` page (admin panel) must not be indexed.
- **Fix**: Add per-route layouts or metadata exports:

```ts
// app/chat/layout.tsx and app/feedback/layout.tsx
export const metadata = { robots: { index: false, follow: false } }
```

**SD-1 — No structured data / JSON-LD schema**

- The homepage has a full FAQ section using `<details>`/`<summary>` but no `FAQPage` JSON-LD schema.
- There is no `WebSite`, `Organization`, or `NGO` schema.
- `FAQPage` schema can unlock FAQ rich results in Google SERPs, which is high-value for crisis queries like "如何申请人身安全保护令".
- **Fix**: Add JSON-LD to the root layout and homepage:

```tsx
// In app/page.tsx (or its wrapper layout), add:
<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{ __html: JSON.stringify({
    "@context": "https://schema.org",
    "@type": "WebSite",
    "name": "小安反家暴助手",
    "url": "https://anti-dv.vercel.app/",
    "description": "反家庭暴力AI支持助手"
  })}}
/>
```

  Add a separate `FAQPage` schema block for the homepage FAQ accordion items.

### Medium-Priority Findings (P2)

**PERF-1 — Google Fonts loaded via CSS `@import` (render-blocking)**

- [app/styles/globals.css](app/styles/globals.css) imports Noto Serif SC and Noto Sans SC from `fonts.googleapis.com` via `@import`. CSS `@import` is render-blocking and delays the First Contentful Paint (FCP).
- **Fix**: Move font loading to `<link rel="preconnect">` + `<link rel="stylesheet">` in `app/layout.tsx`, or use `next/font/google`:

```ts
import { Noto_Sans_SC, Noto_Serif_SC } from 'next/font/google'
const notoSans = Noto_Sans_SC({ subsets: ['latin'], weight: ['400', '500', '700'], display: 'swap' })
```

  Using `next/font` automatically self-hosts, eliminates external DNS lookup, and removes the render-blocking request.

**SEC-2 — No security response headers configured**

- [next.config.js](next.config.js) has no `headers()` configuration. The site is missing standard security headers that also affect crawler trust signals:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY` (important for domestic violence context — prevents clickjacking)
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Content-Security-Policy` (at minimum a basic policy)
- **Fix**: Add a `headers()` async function in `next.config.js`.

**CANON-1 — No canonical tags**

- No `<link rel="canonical">` tags visible on any page. Without these, Vercel preview deployments and any staging URL could be treated as duplicate content by Google.
- **Fix**: Setting `metadataBase` in the root metadata (as described in META-2 above) and exporting `metadata` per page will cause Next.js to automatically inject canonical tags.

**BUILD-1 — TypeScript and ESLint errors silently ignored in production**

- [next.config.js](next.config.js#L15) has both `typescript.ignoreBuildErrors: true` and `eslint.ignoreDuringBuilds: true`. This means broken code, type mismatches, and accessibility linting issues are silently deployed to production.
- **Fix**: Remove both flags (or at least `typescript.ignoreBuildErrors`) and address the underlying TS errors. The ESLint config can be kept permissive, but TypeScript safety should be enforced.

### Low-Priority Findings (P3)

**I18N-1 — No `hreflang` tags despite 6-language support**

- The site supports zh/en/es/fr/ja/vi (i18n config confirmed). No `hreflang` alternate tags are present.
- For a Chinese-language domestic violence chatbot with primarily mainland Chinese users, this has minimal SEO impact right now. However, if the en/es/fr/vi language routes are active, Google needs `hreflang` to avoid treating them as duplicates.
- **Fix**: Low priority. Address after metadata is established.

**PERF-2 — Hero background image from external CDN (potential LCP risk)**

- The homepage hero section references a background image from Pexels CDN as an inline CSS style. This is not `preload`-hinted, and the image is loaded after CSS parsing, delaying LCP.
- **Fix**: Move to a self-hosted image in `/public/` and reference it via `next/image` with `priority` prop, or add a `<link rel="preload">` hint.
