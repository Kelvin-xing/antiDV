## Remaining Issues

### 🔴 P0 — HTTP 500 Still Present on ALL Public Pages

**Confirmed by:**
```
/ → 500
/resources → 500
/stories → 500
/psych-resources → 500
/docs-toolkit → 500
/chat → 500
```

RSC error digest has changed from `3116509932` (v2) to `3549000446` (v3), indicating a different error in the newly-deployed build — the error persists but is not the same crash as before. This is a regression introduced in the new deployment.

The HTML confirms:
```html
<html id="__next_error__">
```
No `lang` attribute is present on the `<html>` tag when Next.js renders an error page — it strips all layout-level attributes.

---

### 🔴 P0 — `noindex` Still Injected Site-Wide by Error Handler

**Confirmed by:** `<meta name="robots" content="noindex"/>` present on all pages.

Even though metadata (title, description, OG) is now present in the HTML, the `noindex` directive overrides everything. Google will not index any page while HTTP 500 persists. This is the single highest-priority remaining issue.

**Critical note**: Metadata fixes are effectively invisible to Google until the HTTP 500 is resolved. All the metadata work is correct and ready — it just cannot take effect yet.

---

### 🟠 P1 — No Canonical URLs

**Confirmed by:** No `<link rel="canonical">` found on any page.

Canonical URLs were not part of the deployed fixes. Without canonicals, Google may encounter duplicate-content issues across RSC variations and mobile/desktop URLs. Should be added to `app/layout.tsx` and per-route layouts.

---

### 🟠 P1 — JSON-LD Not in Static `<script>` Tags

FAQPage JSON-LD is present in the RSC payload but is injected via `dangerouslySetInnerHTML` rather than a proper `<script type="application/ld+json">` tag. On an HTTP 500 error page, Google's rendering pipeline may not execute the JavaScript needed to insert this into the DOM. The structured data is effectively invisible to Google while HTTP 500 persists.

No `WebSite` or `Organization` schema is deployed.

---

### 🟡 P2 — `<html lang>` Attribute Missing on Error Pages

**Confirmed by:** `<html id="__next_error__">` — no `lang="zh"` attribute.

When Next.js renders an error page, it uses its own internal `<html>` template that does not inherit the `lang` attribute from your root layout. This is a known limitation of the Next.js App Router error page behavior. Fix: add an `error.tsx` root error boundary that renders a proper layout, or resolve the HTTP 500 so the normal root layout renders.

---

### 🟡 P2 — No Google Search Console Submission

Even though sitemap.xml is now live, it has not been submitted to Google Search Console (GSC) or Baidu Webmaster Tools. Without submission, Google may not crawl it promptly, especially on a Vercel subdomain with no domain authority.

---

### 🟡 P2 — Cache-Control: no-store on All Routes

**Confirmed by:** `cache-control: private, no-cache, no-store, max-age=0, must-revalidate` on all routes.

Pages cannot be edge-cached by Vercel's CDN while HTTP 500 persists and `no-store` is set. Even after resolving the 500, the `no-store` directive may need tuning for static/semi-static pages (e.g., /resources, /stories) to improve Core Web Vitals.

## Priority Action Plan (v3)

### P0 — Fix HTTP 500 (Blockes Everything)

The new RSC error digest `3549000446` was introduced by the latest deployment — this is likely a Server Component in the new code that fails at render time. **Most likely causes:**

1. One of the new `layout.tsx` files (route-level metadata exports) references an environment variable or server-side import that fails in Vercel production.
2. The new `app/sitemap.ts` or `app/robots.ts` may have an async operation that throws.
3. A Server Component in the root layout throws an unhandled exception.

**Debug steps:**
```bash
# Check Vercel function logs for the new error
# In Vercel dashboard: Functions → View logs → filter by 500

# Locally reproduce:
pnpm build
pnpm start
curl -s -I http://localhost:3000/
```

Add an `app/error.tsx` root error boundary as a stopgap — this won't fix the metadata rendering (error.tsx replaces the page slot, not the layout), but it will prevent the full-page `__next_error__` wrapper and allow the `<html lang="zh">` attribute to be preserved.

### P1 — Add Canonical URLs

In each route `layout.tsx`, add:
```typescript
export const metadata: Metadata = {
  // ... existing ...
  alternates: {
    canonical: 'https://anti-dv.vercel.app/[route]',
  },
}
```

### P1 — Move JSON-LD to Static `<script>` Tags

Replace `dangerouslySetInnerHTML` JSON-LD injection with Next.js `<script>` in the `<head>` via the metadata API or a proper `<Script>` component with `strategy="beforeInteractive"`. Alternatively, use Next.js 15's `generateMetadata` with `jsonLd` support.

### P1 — Submit Sitemap to Search Consoles

1. Google Search Console → Sitemaps → `https://anti-dv.vercel.app/sitemap.xml`
2. Baidu Webmaster Tools (百度站长平台) → same sitemap URL

### P2 — Add Organization + WebSite JSON-LD

```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "小安 反家暴AI助手",
  "url": "https://anti-dv.vercel.app",
  "description": "专注于反家庭暴力的AI支持助手"
}
```

### P2 — Add `app/error.tsx` Root Error Boundary

```typescript
'use client';
export default function Error({ error, reset }) {
  return (
    <html lang="zh">
      <body>
        <div>服务暂时不可用，请稍后再试。</div>
      </body>
    </html>
  );
}
```
This preserves the `lang` attribute and prevents the naked `__next_error__` wrapper.
